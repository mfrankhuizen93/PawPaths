## Recommended execution

Start with #14–#17 (architecture, domain alignment, coordinates, and multi-point editing). Do not begin the visual redesign until coordinate persistence and point identity are reliable. Then deliver #18–#24 as the contribution/moderation slice, followed by #25–#28 for discovery and navigation. Finish with #29–#31 for personalization, reviews, and full validation. Issue #31 can run targeted audits earlier, but its full acceptance pass depends on the core flows being available.

## Known blockers and risks

- Existing point records may lack stable IDs; issue [#15](https://github.com/mfrankhuizen93/PawPaths/issues/15) must define a safe compatibility strategy before issue [#17](https://github.com/mfrankhuizen93/PawPaths/issues/17) changes persistence.
- Coordinate persistence is a critical invariant to verify in issue [#16](https://github.com/mfrankhuizen93/PawPaths/issues/16); the source review identifies risk, not a reproduced failure for every point workflow.
- Current form/auth requirements differ from the target short creation journey and detail tabs. Issues [#20](https://github.com/mfrankhuizen93/PawPaths/issues/20) and [#27](https://github.com/mfrankhuizen93/PawPaths/issues/27) must reconcile them with the normative UI guide before changing those interactions.
- The current Nominatim reverse-geocoder is not automatically approved for area-name matching; provider policy and licensing must be validated in issue [#18](https://github.com/mfrankhuizen93/PawPaths/issues/18).
- Pending review payloads can currently be edited, and location-change approval has no base-version conflict check. Issues [#22](https://github.com/mfrankhuizen93/PawPaths/issues/22) and [#23](https://github.com/mfrankhuizen93/PawPaths/issues/23) must establish history preservation and safe concurrent review.
- Saved and visited states have no inspected shared type/API foundation; issue [#29](https://github.com/mfrankhuizen93/PawPaths/issues/29) should not be pulled into the earlier domain-model work without a product decision.
- Branch freshness and deployed behavior must be checked during implementation; this index makes no claim about the checkout's distance from the remote default branch.
